# Saucy Culture — Production Architecture, Deployment & Admin Guide

## 1. Architecture Overview

| Layer | Technology | Role |
| :--- | :--- | :--- |
| **Storefront UI** | React 19 + Vite + Tailwind CSS | Minimal white studio catalog, INR checkout (COD & 0%-fee Direct UPI QR), Wishlist & Restock alerts, Cart recovery hook, Track Order |
| **API & Server** | Express (`src/server/app.ts`) + Vercel Serverless (`api/index.ts`) | Authoritative server-side order pricing, transactional stock deduction, Firebase ID token auth guard, Cloudinary signed upload minting, Web Push dispatch |
| **Database** | PostgreSQL (`DATABASE_URL`) + Drizzle ORM (`src/db/schema.ts`) | Persists products, orders (atomic row-locked inventory reservations), order tracking keys, rate-limit buckets, Our Circle VIPs, cart leads, restock alerts, Web Push subscriptions, store settings, admins, and audit logs |
| **Admin Auth** | Firebase Authentication (Google Sign-In) | Verified on every `/api/admin/*` call via `firebase-admin` ID token verification against the `admins` table (`firestore.rules` is locked default-deny) |
| **Image Uploads** | Cloudinary Signed Upload | Client compresses large photos and uploads directly to Cloudinary using short-lived SHA-1 signatures generated by `/api/admin/cloudinary-signature` |
| **Background Alerts** | Service Worker (`/public/sw.js`) + VAPID (`web-push`) | Delivers restock and cart recovery notifications even when the customer's browser tab or window is closed (endpoints restricted to HTTPS browser push providers) |
| **Audit Trail** | SHA-256 Hash-Chained `admin_audit_logs` | Records every admin mutation (`actorEmail`, role, IP, action, payload, `prevHash`, `entryHash`); only the Store Owner can prune/clear logs |

> **Production Database Requirement:** `DATABASE_URL` is **mandatory** in production (`NODE_ENV=production` / Vercel). Server startup and `/api/health` fail immediately if PostgreSQL is unconfigured. Local `.data/saucy-store.json` is strictly for local non-production preview only.

## 2. Step-by-Step GitHub & Vercel Deployment

### Step 1: Export / Push Code to GitHub
1. Download or sync this project folder to your local machine.
2. Create a new private repository on GitHub (e.g. `saucy-culture-store`).
3. Verify `.gitignore` includes `.env*`, `.data/`, `node_modules/`, and `dist/` (already configured).
4. Push to GitHub:
   ```bash
   git init
   git add .
   git commit -m "Initial Saucy Culture full-stack storefront"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<your-repo>.git
   git push -u origin main
   ```

### Step 2: Connect Your Vercel Project & PostgreSQL Database
1. In **Vercel Dashboard → Add New Project**, import your GitHub repository.
2. Under **Storage** (or Neon / Supabase), connect your PostgreSQL database so Vercel sets `DATABASE_URL` in Project Environment Variables.
   - Make sure the connection string uses SSL (`?sslmode=require`).
3. Push the Drizzle schema to your PostgreSQL database once from your terminal:
   ```bash
   DATABASE_URL="postgresql://..." npm run db:push
   ```
   *(The backend also executes idempotent `CREATE TABLE IF NOT EXISTS` statements on cold start and seeds the starter catalog and Store Owner automatically if tables are empty.)*

### Step 3: Set Up Cloudinary Direct Photo Uploads
1. Create a free account at [cloudinary.com](https://cloudinary.com).
2. From the **Cloudinary Dashboard**, copy:
   - `Cloud Name`
   - `API Key`
   - `API Secret`
3. Add these three environment variables in **Vercel → Settings → Environment Variables**:
   - `CLOUDINARY_CLOUD_NAME`
   - `CLOUDINARY_API_KEY`
   - `CLOUDINARY_API_SECRET`
4. Uploaded images are saved to the `saucy-culture/products` folder inside your Cloudinary media library.

### Step 4: Set Up Background Browser Web Push (VAPID Keys)
1. Generate a free VAPID key pair in your terminal:
   ```bash
   npx web-push generate-vapid-keys
   ```
2. Add the keys to **Vercel → Settings → Environment Variables**:
   - `VAPID_PUBLIC_KEY`
   - `VAPID_PRIVATE_KEY`
   - `VAPID_SUBJECT` (e.g., `mailto:support@saucyculture.in`)
3. How it works in production:
   - Customers who enable push notifications in **Wishlist / Restock Alerts** or the **10% Off Cart Recovery Modal** are registered via `/public/sw.js` and stored in `push_subscriptions`.
   - When an admin restocks a sold-out size (`0` → `1+` units) in **Products & Stock**, the server automatically dispatches background push alerts to subscribed restock watchers.
   - Admins can also trigger targeted push campaigns anytime from **Admin → Leads & Push → Background Browser Push Blast**.
   - *Note:* iOS Safari requires users to tap **Share → Add to Home Screen** (iOS 16.4+) for background Web Push; WhatsApp & Email capture remain active as universal fallback channels.

### Step 5: Authorize Your Vercel Domain in Firebase Auth
1. Open **Firebase Console → Project `silken-impulse-442300-f0` → Authentication → Settings → Authorized domains**.
2. Click **Add domain** and add:
   - Your Vercel URL (e.g. `saucy-culture.vercel.app`)
   - Your custom domain once connected (e.g. `saucyculture.in`, `www.saucyculture.in`)
3. Without this step, Google Sign-In popups on `/admin` will be blocked on the live Vercel domain.

### Step 6: `/admin` Refresh Fix on Vercel
- `vercel.json` is configured with:
  - `/api/(.*)` → `/api/index` (Express serverless function)
  - `/((?!api/|assets/|src/|sw\\.js).*)` → `/index.html` (SPA client router fallback)
- Visiting or hard-refreshing `https://your-domain.com/admin` loads cleanly with HTTP `200`.

## 3. Admin Roles & Client Onboarding

1. **Store Owner (`OWNER`):** `spiritofhinduism@gmail.com`
   - Full access to Orders, Products & Stock, Leads & Push, Storefront CMS & UPI Settings, Team Access, and **Audit Log Management**.
   - Cannot be removed by any other admin.
   - **Only the Owner** can archive (`Keep Latest 50`) or clear entries in the Audit Log, or remove other invited admins.
2. **Client / Staff Admin (`ADMIN`):**
   - Invited by adding their verified Google / Workspace email inside **Admin → Settings & Team**.
   - Can fulfill & dispatch orders, confirm COD / verify UPI UTRs, add/edit/delete products, upload Cloudinary photos, edit Hero & Storefront settings, and send push blasts.
   - **Cannot** delete or alter Audit Log entries, **cannot** remove the Store Owner, and **cannot** revoke team members.

## 4. How the Tamper-Evident Audit Log Works

Every state-changing `/api/admin/*` request appends a record to `admin_audit_logs` containing:
- `seq`: Strictly sequential entry counter
- `actorEmail` & `actorRole`: Verified directly from the Firebase Google ID token on the server (cannot be spoofed from the browser)
- `ipAddress`: Request IP extracted from `x-forwarded-for` / socket
- `action`, `entityType`, `entityId`, `detailsJson`, `createdAt`
- `prevHash` & `entryHash`: **SHA-256 cryptographic hash chain** linking each entry to the previous entry (`entryHash = SHA256(seq | actorEmail | actorRole | action | entityType | entityId | detailsJson | prevHash | createdAt)`)

Whenever **Admin → Audit Log** is opened, the server calls `verifyAuditChain()` across all stored entries:
- If every hash and sequence matches, the console displays **SHA-256 Chain Verified**.
- If any database row was manually altered or silently deleted outside the app, the UI flags the exact `seq` number where the hash chain broke.
